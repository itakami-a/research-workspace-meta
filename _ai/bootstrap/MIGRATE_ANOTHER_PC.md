# 別PCからの安全な移行

## 目的

旧 `research` の大量な日付作業フォルダは引き継がず、その中に散在するルール、プロンプト、Skill候補だけを回収します。Git管理ディレクトリは、両端末の状態を比較してから一つずつ揃えます。

## 前提

- 先にこのメタリポジトリを別PCへcloneする
- 旧 `research` は最初は読み取り専用で調査する
- 調査と移植を同じ操作にしない
- `team/` と `external/` は、別PCでもAI読み取り専用とする

## Phase 1: ルール候補の発見

旧 `research` 内から、次の名前や場所を読み取り専用で探します。

- `AGENTS.md`、`GEMINI.md`、`CLAUDE.md`、`RULE.md`
- `.cursor/rules/**/*.mdc`
- `.agents/skills/**/SKILL.md`、`.codex/**`
- `rules/`、`prompts/`、`skills/`、`instructions/`
- MCP、フック、エージェント設定の雛形
- README内に書かれた作業規則、禁止事項、検証手順

発見した各候補について、パス、概要、適用範囲、現在も必要か、他の規則との衝突、推奨保存先を `INVENTORY.md` に記録します。この段階ではコピー、編集、削除を行いません。

## Phase 2: 原文の保全

ユーザーが一覧を確認した後、採用候補のルール系ファイルだけを次へコピーします。

`_ai/imports/<device-name>-<YYYY-MM-DD>/raw/`

ファイル名が衝突する場合は、旧パスが分かる名前にします。旧文書の指示をそのまま有効化せず、出典資料として保持します。

## Phase 3: 統合

`MAPPING.md` に、原文から正式な保存先への対応を記録します。

- 絶対に忘れてはいけない境界 → ルート `AGENTS.md`
- 長い運用説明 → `_ai/rules/`
- 新規プロジェクト共通の文脈 → `_ai/templates/project/`
- 繰り返し使う手順 → `_ai/skills-src/`
- 再利用する依頼文 → `_ai/prompts/`
- 外部接続の設定例 → `_ai/mcp/`
- 研究テーマ固有 → 対応するプロジェクト

重複する規則は一つに統合し、矛盾する場合はユーザーに判断を求めます。統合後に、採用、統合、廃止、保留を記録します。

## Phase 4: Gitリポジトリの比較

両端末で各リポジトリについて次を記録します。

- 絶対パス
- `origin` URL
- 現在のbranch
- HEAD commit hash
- upstream
- 未コミット変更と未追跡ファイルの件数
- 最終commit日時

比較が終わるまで `pull`、`reset`、`checkout`、`clean`、削除、上書きを行いません。詳細は `REPO_RECONCILIATION.md` を参照します。

## Phase 5: 旧作業フォルダ

必要なルールの移植と検証が終わっても、旧 `research` を自動削除しません。不要であることをユーザーが確認した後、別途アーカイブまたは削除を判断します。
